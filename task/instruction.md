The input data is located under /app/data and contains the following JSON collections:
- customers.json
The directory /app/data contains three JSON document collections:

- customers.json
- products.json
- orders.json

Analyze these collections and produce one JSON file only:

/app/report.json

The output must be valid UTF-8 JSON and contain only these top-level fields:

{
  "total_revenue": 0.0,
  "active_customers": 0,
  "cancelled_orders": 0,
  "top_customer": {
    "customer_id": "",
    "total_spend": 0.0
  },
  "top_product": {
    "product_id": "",
    "quantity_sold": 0
  },
  "category_revenue": {}
}

Required calculations:

total_revenue:
Compute the combined net revenue from every non-cancelled order. For each purchased line item, revenue is calculated from its unit price and quantity after subtracting any line-item discount. Round the final result to two decimal places.

active_customers:
Count distinct customers that occur in at least one non-cancelled purchased line item. Customer identifiers are case-insensitive, so identifiers differing only in letter case represent the same customer.

cancelled_orders:
Count logical orders containing at least one cancelled line item.

top_customer:
Find the customer with the greatest cumulative spend from non-cancelled purchased line items. Return exactly:
{
  "customer_id": "...",
  "total_spend": 0.0
}
The ID must be uppercase and the spend must be rounded to two decimal places. When customers tie, choose the uppercase customer ID that comes first lexicographically.

top_product:
Find the product with the greatest number of units sold from non-cancelled purchased line items. Return exactly:
{
  "product_id": "...",
  "quantity_sold": 0
}
The product ID must be uppercase and the quantity must be an integer. When products tie, choose the uppercase product ID that comes first lexicographically.

category_revenue:
Create a mapping from each authoritative product category to the revenue generated by its non-cancelled purchased line items. Round each value to two decimal places. Every category with revenue after reconciliation must occur exactly once.

The collections may contain multiple representations of the same logical customer, product, or order. Each representation has a schema_version field. Before performing any joins, filtering, or aggregation, retain only the representation with the highest schema_version for each logical entity.

Different schema versions may use different field names or document layouts. Inspect the supplied collections and normalize these representations before calculating the metrics.

For products, the category in the retained highest-version product document is authoritative.

Orders can contain cancellations at the individual line-item level. Exclude cancelled line items from revenue, customer, and product calculations, rather than discarding the entire order. An order containing at least one cancelled line item contributes to cancelled_orders.

Do not create any output other than /app/report.json.  {
    "customer_id": "...",
    "total_spend": ...
  }
  where customer_id is a string converted to uppercase, and total_spend is a number rounded to exactly two decimal places.
- top_product (object): Must contain exactly the following structure for the product with the highest total units sold across non-cancelled orders:
  {
    "product_id": "...",
    "quantity_sold": ...
  }
  where product_id is a string converted to uppercase, and quantity_sold is an integer.
- category_revenue (object): A key-value map where keys are category names (string) and values are total net revenue (number, rounded to exactly two decimal places) for non-cancelled orders. All categories with non-zero revenue present in the dataset must appear. Orders with missing or blank categories must be grouped under key "Uncategorized".

Tie-Breaking Rules:
- top_customer: If multiple customers tie for highest spend, select the customer whose uppercase customer_id comes first lexicographically (ASCII order).
- top_product: If multiple products tie for highest total quantity sold, select the product whose uppercase product_id comes first lexicographically (ASCII order).

Do not generate any files other than /app/report.json.
